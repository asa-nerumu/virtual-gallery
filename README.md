# バーチャル展覧会「MUSEUM OF FORMS」公開・セットアップ手順書

この手順書では、バーチャル展覧会アプリをインターネット上に公開し、**管理者や出展者が設置・公開した作品を URL 共有だけで全鑑賞者のブラウザへリアルタイム反映させる**ためのセットアップ手順と運用方法を解説します。

サーバー代は基本的に **無料（Firebase 無料枠＋無料ホスティング）** で運用できます。

## 全体の流れ（所要時間：約10〜15分）

1. **Step 1：Firebase でデータ保存先（クラウド）を作る**（約5〜8分）
2. **Step 2：HTML ファイルに Firebase 設定を書き込む**（約2分）
3. **Step 3：無料ホスティング（GitHub Pages / Netlify Drop）に公開する**（約2分）
4. **Step 4：管理者ログイン・複数アカウント発行・作品展示を行う**（約2分）

---

## Step 1：Firebase プロジェクトの準備（無料）

作品の画像データ・タイトル・公開設定・鑑賞者コメント・アカウント情報を保存するため、Google の **Firebase（Spark プラン：無料）** を設定します。

### 1-1. プロジェクトを作成する

1. [Firebase Console](https://console.firebase.google.com/) に Google アカウントでログインします。
2. **「プロジェクトを作成」** をクリックし、任意の名前（例：`my-virtual-gallery`）を入力して続行します。
3. Google アナリティクスはオフのままで構いません。**「プロジェクトを作成」** を押して完了するまで待ちます。

### 1-2. ウェブアプリを登録して設定値（Config）を取得する

1. プロジェクトの概要画面で、ウェブアイコン **`</>`** をクリックします。
2. アプリのニックネーム（例：`gallery-web`）を入力し、**「アプリを登録」** をクリックします（※Firebase Hosting のチェックは不要です）。
3. 画面に表示される `firebaseConfig` の **`{ ... }` 部分** をコピーしてメモしておきます。

```javascript
// この { から } までをメモしておきます
{
  apiKey: "AIzaSy...",
  authDomain: "〇〇.firebaseapp.com",
  projectId: "〇〇",
  storageBucket: "〇〇.firebasestorage.app",
  messagingSenderId: "〇〇",
  appId: "1:〇〇:web:〇〇"
}
```

### 1-3. 匿名認証（Authentication）を有効にする

鑑賞者や管理者・出展者が安全にクラウドへ接続できるよう、匿名認証をオンにします。

1. 左メニューの **「構築」**（または「プロダクトのカテゴリ」＞「セキュリティ」）から **「Authentication」** を開き、**「始める」** をクリックします。
2. **「Sign-in method」** タブから **「匿名」** を選択します。
3. **「有効にする」** をオンにして **「保存」** をクリックします。

### 1-4. データベース（Cloud Firestore）を作成する

※ 似ている名前の「Realtime Database」ではなく、**「Firestore Database」** を使用します。

1. 左メニューの **「構築」**（または「プロダクトのカテゴリ」＞「Database と Storage」）から **「Firestore Database」** を開き、**「データベースの作成」** をクリックします。
2. ロケーションは **`asia-northeast1`（東京）** などを選択して「次へ」を押します。
3. セキュリティルールは **「本番環境モードで開始」** または **「テストモードで開始」** を選んで作成します。
4. 作成後、上部タブの **「ルール」** を開き、既存の内容をすべて消してから以下の9行だけを貼り付けて **「公開」** をクリックします。

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /artifacts/{appId}/public/data/{collection}/{document} {
      allow read, write: if request.auth != null;
    }
  }
}
```

## Step 2：HTML ファイルに Firebase 設定を書き込む

1. `virtual_gallery.html` をパソコンに保存し、公開用ファイル名 **`index.html`** にリネームします。
2. メモ帳や VS Code などのテキストエディタで開き、**`★ 公開用設定エリア（ここだけ書き換えればOK！）`** を探します。
3. `USER_FIREBASE_CONFIG` に Step 1-2 で取得した `{ ... }` が入っていることを確認して保存します（※すでに設定済みの場合はそのまま Step 3 へ進めます）。

```javascript
const USER_GALLERY_ID = 'my-gallery-01'; // 展覧会ごとの識別ID（半角英数字・ハイフン推奨）

const USER_FIREBASE_CONFIG = {
  apiKey: "ここにメモしたapiKeyを貼る",
  authDomain: "〇〇.firebaseapp.com",
  projectId: "〇〇",
  storageBucket: "〇〇.firebasestorage.app",
  messagingSenderId: "〇〇",
  appId: "〇〇"
};
```

> **ヒント**：複数の展覧会を同じ Firebase プロジェクトで運用したい場合は、`USER_GALLERY_ID` の文字列（例：`exhibition-2026-spring`）を変えるだけでデータを分離できます。

## Step 3：インターネットに公開して URL を発行する

### 方法A：GitHub Pages を使う

1. GitHub で公開用リポジトリを作成し、**`index.html`** と **`README.md`**（この手順書）をアップロード（Commit changes）します。
2. リポジトリの **`Settings` ＞ 左メニューの `Pages`** を開きます。
3. **「Branch」** を **`main`**、フォルダを **`/ (root)`** に設定して **`Save`** を押します。
4. 1〜2分後に画面上部に `https://ユーザー名.github.io/リポジトリ名/` の公開 URL が発行されます。

### 方法B：Netlify Drop を使う（もっとも簡単・ソース非公開運用も可）

1. パソコン上に新しい空のフォルダ（例：`my-gallery`）を作り、その中に `index.html` を 1 つだけ入れます。
2. [Netlify Drop](https://app.netlify.com/drop) をブラウザで開き、**`my-gallery` フォルダごとドラッグ＆ドロップ** すると数秒で公開 URL が発行されます。

## Step 4：ログイン・複数アカウント発行・作品展示

発行された公開 URL にアクセスし、ヘッダー左上のステータスが緑色の **`LIVE`** になっていればクラウド連携は完了です。

### 1. マスター管理者としてログイン＆パスワード変更（必須）

1. ヘッダー右上の **鍵アイコン（🔒）** をクリックします。
2. 初回デフォルトの ID / パスワードを入力してログインします。
   * **マスター管理者ID**：`admin`
   * **パスワード**：`gallery2026`
3. ログイン後、**「展示・管理」＞「展覧会・アカウント管理」** タブを開き、**公開前に必ずマスター管理者のパスワードを推測されにくいものへ変更** してください。

### 2. 出展者・共同スタッフ用の複数 ID / パスワードを発行する

グループ展や共同キュレーションを行う場合、同じ **「展覧会・アカウント管理」** タブの下部から、メンバーごとに専用のログインID・パスワードを何人でも発行できます。

* **出展者（担当枠のみ編集可）**：空きスロットへの新規展示と、自分が設置した作品のみの編集・公開切替・撤去・コメント管理が可能。他の出展者の作品は誤って編集できない安全設計です。
  * **重要**：初回起動時は全8スロットにサンプル作品が展示されているため、出展者に作品を展示してもらう前に、マスター管理者が **「展示スロット一覧」から該当スロットを「撤去」して空き枠を用意** してください。
* **共同キュレーター（全スロット編集可）**：マスター管理者と同様に全8スロットの編集・公開切替が可能（アカウント発行と全体リセットはマスター管理者限定）。

### 3. 作品を展示して URL を共有する

* **「作品を展示 / 編集」** タブから画像をドラッグ＆ドロップして保存すると、鑑賞者全員の 3D 空間へリアルタイムに反映されます。
* 準備中の作品は **公開ステータスを「下書き（非公開）」** にしておくと、管理者と作成者だけに半透明プレビューが表示され、一般鑑賞者には空の壁として隠れます。
* 準備ができたらヘッダーの **「展覧会を共有」** ボタンで URL をコピーし、SNS やメールで案内してください。

## トラブルシューティング・よくある質問

### Q. ヘッダーのステータスが `OFFLINE` や `LOCAL` になる

* **確認1**：Firebase Console で **Authentication の「匿名」が有効** になっているか確認してください。
* **確認2**：Firestore の **「ルール」** が Step 1-4 のコード通りに公開されているか確認してください。

### Q. Firebase の無料枠で複数人の管理者・鑑賞者が同時アクセスしても大丈夫？

* Spark プラン（無料枠）では、Firestore の保存容量 1GB・読み取り 5万回/日・書き込み 2万回/日まで無料です。管理者が複数人同時にログインして作品を設置しても、負荷や容量はほとんど増えず無料枠内で十分に運用できます。
